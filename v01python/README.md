# SSR 웹개발

LLM을 일종의 '주니어 개발자' 혹은 '페어 프로그래밍 파트너'로 두고 프로젝트를 유지보수할 때, 가장 중요한 원칙은 "명시성(Explicit)", "응집성(Co-location)", "표준화(Standard)"입니다.

LLM은 맥락(Context)이 끊기거나, 파일이 너무 여러 개로 흩어져 있거나, 타입이 불분명할 때 환각(Hallucination)을 일으키고 엉뚱한 코드를 짜기 시작합니다. 이를 방지하고 유지보수를 극대화하기 위한 풀스택 스펙과 설계 규칙을 정리해 드립니다.

---

## Gradio vs Next.js: Claude Code 유지보수 관점 비교

좋은 질문입니다. 결론부터 말하면 **"프로젝트 성격에 따라 다르다"** 이며, 특히 **AI/ML 데모나 내부 도구라면 Gradio/Streamlit이 압도적으로 유리**합니다.

---

## 🎯 핵심 결론 (TL;DR)

| 상황 | 추천 |
|------|------|
| AI/ML 데모, PoC, 내부 도구 | **Gradio** ⭐ |
| 데이터 대시보드, 분석 도구 | **Streamlit** ⭐ |
| 어드민 패널, CRUD 위주 | **Reflex** 또는 **NiceGUI** |
| 일반 사용자 대상 프로덕트 | **Next.js** |
| 복잡한 UI/UX, 디자인 중요 | **Next.js** |

## ❌ Gradio/Streamlit의 단점 (Claude Code 관점)

### 1. **커스터마이징 한계 = LLM이 "할 수 없는 것"이 많음** ⚠️
- 디자인 자유도 낮음 → "이렇게 바꿔줘" 요청해도 한계
- 특정 UI 요청 시 Claude가 **CSS 해킹이나 monkey-patching** 시도 → 코드 품질 저하
- Streamlit의 경우 `st.markdown(unsafe_allow_html=True)` 남발하게 됨

### 2. **상태 관리 모델이 독특함**
- **Streamlit**: 매 인터랙션마다 스크립트 전체 재실행 → LLM이 종종 혼란
  - `st.session_state` 패턴을 반복적으로 틀림
  - "왜 변수가 초기화되지?" 같은 디버깅 자주 발생
- **Gradio**: 이벤트 기반이지만 `gr.State` 사용법이 직관적이지 않음

### 3. **확장 시 구조가 무너짐**
- 작을 땐 천국, 커지면 지옥
- 한 파일에 1000줄 넘어가면 Claude도 길을 잃음
- 컴포넌트 재사용 패턴이 약함 (특히 Streamlit)

### 4. **라우팅/멀티페이지 약점**
- Streamlit의 `pages/` 디렉토리는 제한적
- Gradio는 멀티페이지 자체가 어색함
- 복잡한 네비게이션 = 억지로 짜야 함 → Claude가 안티패턴 생성

### 5. **인증/세션 관리 빈약**
- 프로덕션 인증은 별도 리버스 프록시(OAuth2 Proxy 등) 필요
- Claude가 이걸 직접 구현하려다 보안 구멍 만들 위험

### 6. **실시간/스트리밍 제약**
- WebSocket 커스텀 사용 어려움
- 복잡한 실시간 동기화는 Next.js가 압도적

### 7. **테스트 어려움**
- UI 자동화 테스트 도구가 빈약
- Claude가 테스트 코드 짜기 어려움 → 회귀 버그 위험

## 💡 최종 권장 의사결정 트리

```
프로젝트가 AI/ML 데모인가?
├─ YES → Gradio
└─ NO →
   데이터 시각화/대시보드 위주인가?
   ├─ YES → Streamlit
   └─ NO →
      내부 도구/어드민인가?
      ├─ YES → Reflex 또는 NiceGUI
      └─ NO →
         일반 사용자용 프로덕트인가?
         └─ YES → Next.js (이전 답변 참조)
```

## 🔑 핵심 통찰

**Claude Code 유지보수성 = 단순히 코드량이 적은 것이 아닙니다.**

- **단순한 작업**에서는 Python 단일 스택(Gradio)이 압도적으로 유리
- **요구사항이 프레임워크 한계를 넘으면** Claude가 "해킹성 코드"를 짜기 시작 → 오히려 부채 증가
- **"내 프로젝트가 6개월 후 어디까지 갈 것인가?"** 를 먼저 판단하세요

> 💬 추천: **PoC는 Gradio로 빠르게 → 프로덕션 가닥 잡히면 Next.js로 마이그레이션**도 좋은 전략입니다. FastAPI 백엔드를 그대로 두면 마이그레이션 비용이 낮아집니다.
